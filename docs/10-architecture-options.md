
# Анализ архитектурных опций

Перед выбором архитектуры были рассмотрены несколько архитектурных
подходов. Основной задачей было выбрать архитектуру, которая позволит
системе масштабироваться при росте пользователей, поддерживать
интеграции с внешними сервисами и быть удобной для разработки
несколькими командами.

Были рассмотрены следующие варианты архитектуры:
| Архитектура | Плюсы | Минусы | Решение |
|---|---|---|---|
| Монолит | Простота | Плохая масштабируемость | Не выбран |
| Модульный монолит | Логическая структура | Ограниченная масштабируемость | Не выбран |
| Serverless | Автоматическое масштабирование | Ограничения логики | Не выбран |
| Микросервисы | Масштабируемость | Сложнее инфраструктура | Выбран |

## Обоснование выбора

В результате анализа была выбрана микросервисная архитектура.

Основные причины выбора:

- система ориентирована на глобальную аудиторию
- разные компоненты системы имеют различную нагрузку
- требуется возможность независимого масштабирования сервисов
- в компании работает большое количество разработчиков

Микросервисная архитектура позволяет разделить систему на
независимые сервисы и развивать их отдельно.
