# 12. Сценарии использования приложения

Описанные сценарии отражают ключевую ценность системы:
запись тренировок, анализ прогресса, социальное взаимодействие,
участие в соревнованиях и интеграцию с внешними устройствами
и системами компании.

Сценарии использования отражают ключевые возможности системы
и покрывают основные бизнес-требования:

- работа пользователей с системой
- запись и анализ тренировок
- социальное взаимодействие
- участие в соревнованиях
- интеграции с устройствами и системами компании

---

## UC-01. Регистрация и вход в систему

### Цель
Зарегистрировать нового пользователя платформы или авторизовать существующего.

### Основные участники
- пользователь
- мобильное приложение
- Identity Service

### Предусловия
- приложение установлено

### Основной сценарий
1. Пользователь открывает приложение
2. Выбирает регистрацию или вход
3. Вводит данные
4. Система проверяет данные
5. Создается учетная запись или выполняется вход
6. Пользователь получает доступ к системе

### Альтернативный сценарий
- пользователь уже зарегистрирован и выполняет только вход

### Исключения
- введены некорректные данные
- учетная запись уже существует
- сервис аутентификации недоступен

### Результат
Пользователь авторизован в системе

---

## UC-02. Запись тренировки

### Цель
Пользователь фиксирует тренировку.

### Основные участники
- пользователь
- мобильное приложение
- Workout Service
- Integration Service

### Предусловия
- пользователь авторизован

### Основной сценарий
1. Пользователь запускает тренировку
2. Приложение получает данные с сенсоров
3. Данные передаются в систему
4. Тренировка сохраняется
5. Пользователь завершает тренировку
6. Система отображает результат

### Альтернативный сценарий
- пользователь вводит данные тренировки вручную

### Исключения
- отсутствует доступ к датчикам
- ошибка передачи данных
- сервис недоступен

### Результат
Тренировка сохранена в системе

---

## UC-03. Подключение внешнего устройства

### Цель
Получение данных с внешних устройств.

### Основные участники
- пользователь
- мобильное приложение
- Integration Service

### Предусловия
- пользователь авторизован

### Основной сценарий
1. Пользователь выбирает устройство
2. Выполняется подключение
3. Начинается синхронизация
4. Данные поступают в систему

### Альтернативный сценарий
- пользователь подключает устройство через стороннее приложение
  (например, Apple Health / Google Fit)

### Исключения
- устройство не найдено
- ошибка подключения
- несовместимость устройства

### Результат
Устройство подключено и передает данные

---

## UC-04. Просмотр и анализ тренировки

### Цель
Оценка результатов тренировки.

### Основные участники
- пользователь
- мобильное приложение
- Workout Service

### Предусловия
- есть сохраненные тренировки

### Основной сценарий
1. Пользователь открывает историю
2. Выбирает тренировку
3. Система отображает показатели
4. Показывается сравнение с предыдущими результатами

### Альтернативный сценарий
- просмотр агрегированной статистики без выбора конкретной тренировки

### Исключения
- ошибка загрузки данных

### Результат
Пользователь получает информацию о прогрессе

---

## UC-05. Поиск пользователей и групп

### Цель
Найти партнеров для тренировок.

### Основные участники
- пользователь
- мобильное приложение
- Social Service

### Предусловия
- пользователь авторизован

### Основной сценарий
1. Пользователь открывает поиск
2. Указывает параметры
3. Система показывает результаты
4. Пользователь присоединяется к группе или пользователю

### Альтернативный сценарий
- система предлагает рекомендации автоматически

### Исключения
- нет подходящих результатов
- ошибка поиска

### Результат
Пользователь находит сообщество или пользователя

---

## UC-06. Публикация результата

### Цель
Поделиться результатами с другими пользователями.

### Основные участники
- пользователь
- Feed Service
- Notification Service

### Предусловия
- тренировка завершена

### Основной сценарий
1. Пользователь публикует результат
2. Запись появляется в ленте
3. Другие пользователи взаимодействуют(читают или оставляют комментарий) с записью
4. Пользователь получает уведомления

### Альтернативный сценарий
- публикация только для ограниченного круга пользователей

### Исключения
- ошибка публикации
- сервис уведомлений недоступен

### Результат
Результат опубликован в системе

---

## UC-07. Участие в соревновании

### Цель
Повысить вовлеченность пользователя.

### Основные участники
- пользователь
- Challenge Service
- Workout Service

### Предусловия
- пользователь авторизован

### Основной сценарий
1. Пользователь выбирает соревнование
2. Присоединяется к нему
3. Выполняет тренировки
4. Система обновляет рейтинг
5. Пользователь отслеживает результаты

### Альтернативный сценарий
- пользователь получает приглашение в соревнование
  от друга, группы или организатора
- переходит по уведомлению или ссылке-приглашению

### Исключения
- соревнование завершено
- пользователь не соответствует условиям

### Результат
Пользователь участвует в соревновании

---

## UC-08. Получение персонализированных рекомендаций

### Цель
Повысить вовлеченность и продажи.

### Основные участники
- пользователь
- Promo сервис
- Integration Service

### Предусловия
- есть данные о пользователе

### Основной сценарий
1. Система анализирует данные пользователя
2. Формирует рекомендации
3. Пользователь получает предложение
4. Пользователь взаимодействует с предложением

### Альтернативный сценарий
- пользователь сам открывает раздел рекомендаций или промо-предложений
- система запрашивает актуальные рекомендации на основе профиля,
  истории активности и выбранного вида спорта
- пользователю отображаются персонализированные предложения
- пользователь выбирает интересующее предложение

### Исключения
- недостаточно данных
- ошибка аналитического сервиса

### Результат
Пользователь получает персонализированные предложения
