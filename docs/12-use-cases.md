# 12. Сценарии использования приложения

Сценарии использования описывают основные способы взаимодействия
пользователей и внешних систем с платформой.

Данные сценарии выбраны как наиболее важные для проекта,
так как они отражают ключевую ценность системы:
отслеживание тренировок, анализ прогресса, социальное
взаимодействие, участие в соревнованиях и интеграцию
с устройствами и экосистемой компании.

---

## UC-01. Регистрация и вход в систему

### Цель
Пользователь получает доступ к платформе и может начать
использование всех основных функций приложения.

### Основные участники
- пользователь
- мобильное приложение
- Identity Service

### Предусловия
- приложение установлено на устройстве пользователя

### Основной сценарий
1. Пользователь открывает приложение
2. Выбирает регистрацию или вход
3. Вводит необходимые данные
4. Система выполняет проверку данных
5. Создается учетная запись пользователя или выполняется вход
6. Пользователь получает доступ к системе

### Результат
Пользователь успешно зарегистрирован или авторизован
и может пользоваться платформой.

---

## UC-02. Запись тренировки с телефона

### Цель
Пользователь фиксирует тренировку с помощью мобильного приложения
и встроенных функций смартфона.

### Основные участники
- пользователь
- мобильное приложение
- Workout Service
- Integration Service

### Предусловия
- пользователь авторизован
- у приложения есть доступ к необходимым функциям устройства
  (например, GPS или сенсорам)

### Основной сценарий
1. Пользователь запускает тренировку в приложении
2. Приложение получает данные со встроенных сенсоров телефона
3. Данные передаются в систему
4. Система сохраняет тренировку
5. После завершения тренировки пользователь получает результат

### Результат
Тренировка сохранена в системе и доступна для последующего анализа.

---

## UC-03. Подключение внешнего фитнес-устройства

### Цель
Пользователь подключает внешнее устройство для передачи
данных о тренировках и показателях организма.

### Основные участники
- пользователь
- мобильное приложение
- Integration Service
- Workout Service

### Предусловия
- пользователь авторизован
- устройство доступно для подключения

### Основной сценарий
1. Пользователь открывает раздел подключаемых устройств
2. Выбирает нужное устройство
3. Система выполняет подключение
4. Начинается синхронизация данных
5. Данные с устройства передаются в систему
6. Информация используется при записи и анализе тренировок

### Результат
Внешнее устройство подключено, а данные с него
используются системой.

---

## UC-04. Просмотр и анализ тренировки

### Цель
Пользователь оценивает результаты своей тренировки
и анализирует прогресс.

### Основные участники
- пользователь
- мобильное приложение
- Workout Service

### Предусловия
- в системе есть сохраненные тренировки пользователя

### Основной сценарий
1. Пользователь открывает историю тренировок
2. Выбирает интересующую тренировку
3. Система отображает основные показатели тренировки
4. Система показывает сравнение с предыдущими тренировками
5. Пользователь анализирует свой прогресс

### Результат
Пользователь получает информацию о своих результатах
и динамике тренировок.

---

## UC-05. Поиск пользователей и групп для совместных тренировок

### Цель
Пользователь находит других спортсменов или группы
по интересам, геолокации и активности.

### Основные участники
- пользователь
- мобильное приложение
- Social Service

### Предусловия
- пользователь авторизован
- профиль содержит достаточную информацию для поиска

### Основной сценарий
1. Пользователь открывает раздел поиска
2. Указывает параметры поиска
3. Система выполняет поиск подходящих пользователей и групп
4. Пользователь просматривает результаты
5. Пользователь подписывается, отправляет запрос
   или вступает в группу

### Результат
Пользователь находит сообщество или партнеров
для совместных тренировок.

---

## UC-06. Публикация результата в ленте активности

### Цель
Пользователь делится результатом тренировки
с друзьями или сообществом.

### Основные участники
- пользователь
- мобильное приложение
- Feed Service
- Notification Service

### Предусловия
- пользователь авторизован
- тренировка завершена и сохранена

### Основной сценарий
1. Пользователь выбирает публикацию результата
2. Система формирует запись в ленте активности
3. Публикация становится доступна друзьям и подписчикам
4. Другие пользователи могут ставить реакции и комментарии
5. Пользователь получает уведомления о взаимодействиях

### Результат
Результат тренировки опубликован в ленте активности,
а пользователь вовлечен в социальное взаимодействие.

---

## UC-07. Участие в соревновании или челлендже

### Цель
Пользователь присоединяется к соревнованию и участвует
в достижении целей челленджа.

### Основные участники
- пользователь
- мобильное приложение
- Challenge Service
- Workout Service

### Предусловия
- пользователь авторизован
- соревнование или челлендж доступны для участия

### Основной сценарий
1. Пользователь выбирает соревнование
2. Подтверждает участие
3. Выполняет тренировки в рамках соревнования
4. Результаты передаются в систему
5. Система обновляет рейтинг участников
6. Пользователь просматривает свое место в рейтинге

### Результат
Пользователь участвует в соревновании,
а система отражает его прогресс и место в рейтинге.

---

## UC-08. Получение персонализированного предложения

### Цель
Пользователь получает рекомендации по тренировкам,
экипировке или товарам компании на основе своей активности.

### Основные участники
- пользователь
- мобильное приложение
- Recommendation/Promo компоненты
- Integration Service

### Предусловия
- пользователь авторизован
- в системе есть данные о тренировках и предпочтениях пользователя

### Основной сценарий
1. Система анализирует историю активности пользователя
2. Определяются подходящие рекомендации
3. Пользователь получает персонализированное предложение
4. Пользователь может перейти к подробной информации
   или к покупке товара в системе компании

### Результат
Пользователь получает релевантные рекомендации,
а компания получает дополнительный канал продаж.

---

## Вывод

Описанные сценарии использования отражают основные способы
взаимодействия пользователей с платформой.

Они показывают, что система должна поддерживать:

- доступ пользователей к платформе
- запись и анализ тренировок
- подключение внешних устройств
- социальные взаимодействия
- соревнования и челленджи
- интеграцию с коммерческой экосистемой компании

Данные сценарии будут использоваться далее
при описании базовой архитектуры и архитектурных представлений.
